一、夸克：全部资源 412

怎么定位的

那句文案只由两种情况触发（Play.vue）：媒体元素报 MEDIA_ERR_SRC_NOT_SUPPORTED（静默重试一次后仍失败），或重取播放信息时地址与旧值完全相同。打 7 个新导入分类共 14 条样本走 play → stream(Range)： 14/14 全部 412，而 playMode=proxy、ext 都正确 —— 不是格式、不是前端。错误来自 handler/stream.go:327「源站返回 412」，即直链拿到了，但去源站拉流被拒。

根因

库里存的 cookie 是扫码那一刻的快照，其中 __puus 是夸克 CDN 的准入凭据，陈旧之后： 业务 API（列目录、取直链）照常 200 —— 所以管理端看账号 valid、同步成功、资源列表全正常 —— 只有真去下载时才 412。 于是孩子端"换资源、重进页面"都没用，因为每次取链用的还是那张旧 cookie。

交叉实验（同一文件、同一机器）

组合CDN 结果
旧 cookie 取链 → GET（带 UA + Referer + Cookie）412
同上，去掉 Cookie / 去掉 Referer / 只带 UA / 裸请求 / 换浏览器 UA全部 412
先打一次 /1/clouddrive/config 刷新 __puus，再取链 → GET206 + 真实字节
刷新后但不带 Cookie412

与 Referer/UA 无关，就是 __puus 陈旧；而 CDN 要求 Cookie。

修法

  • GetDirectLink 先刷新 cookie 再取链 —— 链与 cookie 必须"同时新鲜"，只换其中一个都不行。
  • 取链失败强制再刷一次重试（夸克偶发 code=15000）。
  • 刷新值以原始 cookie 为 key 在内存缓存 5 分钟，覆盖"播放信息 + 取流"两次相邻调用。
  • UC 与夸克同属阿里系、同病，一并修（其 __puus 由一次 file/sort 下发）。

参考实现：OpenList drivers/quark_uc 在每个响应里把 Set-Cookie 的 __puus 回写进自己的 cookie 并持久化 —— 印证了方向。

二、百度：两个重叠的 bug（直链从来没成功过）

bug 1 —— 响应形状解析错（根本原因）

/api/filemetas 的真实响应是：

{"errno":0,
 "info":[{"dlink":"https://d.pcs.baidu.com/file/…?fid=…",
          "size":"751828992","fs_id":"1114395303765791", …}],
 "request_id":…}

而代码按 list[].dlink.dlink（嵌套对象）+ 数字 size 解析 —— 键名、dlink 类型、size 类型三处全错， 于是 len(resp.List)==0 恒成立。报错却极具迷惑性：

{"code":500,"message":"获取播放地址失败: 百度获取直链失败: errno=0"}

errno 明明是 0，看着像"接口是好的"，实际是本地没解析出来。这也解释了为什么一直没被发现 —— 线上一条百度资源都没有。

bug 2 —— 拿 BDUSS 冒充 access_token

形状修对之后还有一个坑：dlink 上无条件拼 ?access_token=<BDUSS>。百度在 dlink 上先校验 access_token 再看 Cookie，格式合法的伪令牌直接被判死。

组合（同一条 dlink，717MB mp4）结果
UA=netdisk;P2SP;… + access_token=BDUSS + Cookie401 error_code=110 Access token invalid
UA=netdisk;P2SP;… + 不带 token + Cookie206 video/mp4
UA=pan.baidu.com + 不带 token + Cookie206 video/mp4
任意 UA + 不带 token + 无 Cookie403 error_code=31045 user not exists
  • Cookie（含 STOKEN）是命根子；走 Cookie 鉴权时不能带 access_token。
  • UA 不是关键 —— 两种 UA 都 206，717MB 大文件也不受文档里">20MB 要改 User-Agent: pan.baidu.com"那条影响。
  • AList 只能借思路不能借端点：它走 /xpan/multimedia + 真 OAuth 令牌；该端点在 Cookie 鉴权下恒 404（已实测）。

四、遗留

  • UC 账号 status=invalid（cookie 已失效）→ 需要重新扫码或粘贴 cookie；UC 侧修复因此在线上还没法验证。
  • 百度账号只存在于旧机，且一条百度资源都没有 —— 要用百度内容需要先建映射/导入。
  • 可评估：借 AList 文档给的客户端 ID/密钥走 OAuth refresh_token，比 BDUSS 稳，且能用 /xpan/* 与百度自带转码（/file/v2/play/project）；夸克侧同理可用其转码地址省掉本地转码。
