一、根因：两条独立问题叠加，只修一条都不够

① refreshToken 存了，但从来没被用过

access token 有效期只有 2 小时（config.yaml → jwt.access_expire_hours）。 过期后旧代码的处理是直接清 token 跳登录页 —— 于是"孩子隔天打开 App 必然要重输"成了常态。 而登录时明明已经把 7 天有效期的 refreshToken 写进了 localStorage，却一次都没被调用。

环节修复前修复后
后端 /api/auth/refresh有 ✓有 ✓
登录返回 refreshToken有 ✓有 ✓
前端存 kid_refresh_token存了 ✓存了 ✓
前端用它续期从来没用过 ✗401 自动续期并重放请求 ✓
请求带过期 token→ 收到 401→ refreshToken 换新令牌→ 原请求自动重放→ 孩子无感，留在原页面
  • 续期走裸 axios —— 走 http 实例的话 refresh 自身返回 401 又会触发拦截器，变成自己咬自己。
  • refreshing 变量对并发 401 去重；cfg.__retried 防止无限套娃。
  • 两条 401 路都兜住：后端鉴权失败走 HTTP 200 + body.code=401（util.Fail），但网关也可能直接回 HTTP 401。
  • 只有 refreshToken 本身（7 天）也失效、或账号被停用，才真的回登录页。

二、根因②：Service Worker 把 index.html 锁死在预缓存里

原来 navigateFallback 指向 index.html、而它本身在预缓存清单中 → 所有页面导航都离线优先从缓存喂。孩子端装成 APK 后常年不关，正好卡死在这个模式： 服务端发了新版，App 里也永远跑旧的那份 JS，只有手动清应用数据才能破。

这也是「修了却看不到效果」的元凶 —— 后端和前端代码都对，但新 JS 下不到孩子手上。

navigateFallback'/index.html'null
导航策略预缓存优先（离线优先）NetworkFirst（cacheName kid-pages，6s 超时回退）

六、⚠️ 需要你在平板上做一次操作

必须在平板上手动清一次应用数据，否则这次修复看不到效果 —— 因为当前 App 里跑的还是被旧 SW 缓存的旧 JS，而这次修的正是"新代码下不去"这个鸡生蛋问题。

路径：设置 → 应用 → 小书童 → 存储 → 清除数据（或长按图标 → 应用信息 → 存储 → 清除数据）
之后重新打开，登录一次即可 —— 之后 7 天内都不会再要求输账号密码。

以后再遇到"更新了但客户端还是老样子"，播放页错误态里有「重新加载」按钮（清 SW + Cache 再刷新），点一下就能自救。
