① 目录管理：有映射的目录删不掉

真因不是「有映射」，而是「有资源」

删除代码里把资源的 category_id 置 0，而这一列上有真外键（NO ACTION）：

UPDATE "resources" SET "category_id"=0 ...        ← 撞外键
ERROR: insert or update on table "resources" violates foreign key
constraint "fk_resources_category" (SQLSTATE 23503)

事务随即回滚，接口只回 {"code":500,"message":"删除失败"}。而带映射的目录必然有资源（映射就是往里导资源的），所以你看到的现象就是「目录里有映射就不能删除」。

实测三种场景（改之前）

场景旧行为
空目录删除成功
目录里有资源500 删除失败（日志里就是 23503）
只有映射、没有资源能删，但映射悬空留在「资源映射」页

改法

  • 删目录时跟随软删其（含子目录）资源与资源映射 —— 不再置 0。
  • 响应回传 removedResources / removedMappings，后台弹「删除成功，并清理了 N 个资源、M 条映射」。
  • 确认框写清"其下的资源与资源映射将一并删除，此操作不可撤销"，并显示该目录（含子目录）的资源数。

③ 百度：接入 AList 的路线（与 Cookie 并存）

AList 的做法

refresh_token → access_token（30 天，可续）
/xpan/multimedia?method=filemetas&fsids=[id]&dlink=1   → dlink
HEAD dlink（User-Agent: pan.baidu.com，不跟重定向）      → Location = 真正的 CDN 地址
把 Location 直接交给播放器（浏览器可 302 直连）

本次接进来的部分

位置行为
accessToken()refresh_token → access_token，内存缓存、提前一天失效；client_id/secret 默认用 AList 文档那对
linkViaOAuth()/xpan/multimedia + HEAD(UA=pan.baidu.com、不跟重定向) 取 Location；取不到则退回带 token 的 dlink
ListDir()OAuth 账号（无 cookie）改走 /rest/2.0/xpan/file?method=list
ValidateCookie()OAuth 走 /xpan/nas?method=uinfo（另取 /xpan/quota 的容量）
后台表单百度多一个「刷新令牌」输入框 + AList 授权页链接；Cookie 与刷新令牌二选一

两条路互不干扰：Extra 里配了 refresh_token 就走 OAuth，否则走原来的 Cookie（现有的百度账号没配，所以行为不变，已回归验证 206）。

怎么用

  1. 后台「资源接入 → 手动填写 → 百度网盘」，点表单里的 AList 授权页 链接（也可以直接用下面这条）。
  2. 手机百度 App 扫码授权；回调页会把 refresh_token 显示出来，复制。
  3. 粘到「刷新令牌」框里保存即可（不填 Cookie 也行）。之后校验/列目录/播放都走 OAuth。
https://openapi.baidu.com/oauth/2.0/authorize?response_type=code

  &scope=basic%2Cnetdisk&qrcode=1
限制：OAuth 路线转存分享仍需要 Cookie（转存走的是网页接口，只认 cookie）。要"能播 + 能转存"就两个都填。 另：OAuth 路线的实际效果我还没有端到端验证过 —— 需要一个真实的 refresh_token；你把上面的码扫出来给我，我立刻验。
