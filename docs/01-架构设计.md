# 孩子学习系统 — 架构设计

> 项目代号：**Little Scholar**（给孩子学习系统）
> 版本：v1.0 设计稿
> 定位：自托管的「网盘资源聚合 → 转存分发 → 学习管理 → AI 学情分析」一体化平台

## 1. 需求回顾

### 1.1 后台管理端
| 模块 | 需求要点 |
|---|---|

## 2. 技术选型

### 2.1 已确认决策
| 决策项 | 选择 | 理由 |
|---|---|---|
| 网盘对接 | **自研适配层** | 可控性最强，不依赖第三方服务存活；统一 `DiskAdapter` 接口 |
| 技术栈 | **Go + Vue3** | 与 PanSou / urldb / PanCheck 同栈，可直接借鉴其 SDK 与协议实现；单二进制、镜像小、性能好 |
| 交付节奏 | **分阶段推进** | 每阶段可独立验收，降低返工风险 |
| 安卓端 | **PWA 优先 + WebView 壳** | 一套代码两端复用；息屏播放靠原生壳注入 MediaSession 支持 |

### 2.2 技术栈明细

**后端**
- 语言：Go 1.22+
- Web 框架：Gin
- ORM：GORM
- 数据库：PostgreSQL 15（主库）；Redis 7（缓存 / 任务队列 / 存活检测结果缓存）
- 认证：JWT（后台管理员 + C 端用户双体系）
- 任务队列：Redis List + goroutine worker pool（轻量，不引入 Kafka 等重型依赖）
- 日志：zap
- 配置：viper（支持 .env / yaml / 环境变量）

**前端后台（frontend-admin）**
- Vue 3 + Vite + TypeScript
- UI 库：Element Plus
- 状态：Pinia
- 路由：Vue Router
- 图表：ECharts（学情分析）
- HTTP：Axios

**前端 C 端（frontend-kid / PWA）**
- Vue 3 + Vite + TypeScript
- UI 库：Vant（移动端友好）+ 自定义儿童化主题
- PWA：vite-plugin-pwa（离线缓存、添加到主屏）
- 播放器：`xgplayer`（西瓜播放器，支持 HLS / 弹幕 / 自定义）/ `howler.js`（音频）
- PDF：`pdf.js`
- 套壳 APK：WebView + 原生 MediaSession 桥（支持息屏 / 后台播放）

**外部依赖组件（Docker 编排）**
- `pansou`：资源搜索 + 存活检测（自带 `/api/search`、`/api/check/links`）
- `pancheck`：批量 / 定时存活侦测（可选，作为 pansou 检测的补充）
- `cookie-butler`：扫码获取夸克 / UC / 百度 / 115 / 阿里 cookie（可选择性集成或自研）
- `redis` / `postgresql`：基础存储

### 3.2 核心：网盘适配层设计（★ 项目技术核心）

这是整个系统最关键的部分。四种网盘（夸克/百度/UC/天翼）的协议各不相同，必须抽象成统一接口。

```go
// internal/adapter/adapter.go
type DiskType string

const (
    DiskQuark  DiskType = "quark"
    DiskBaidu  DiskType = "baidu"
    DiskUC     DiskType = "uc"
    DiskTianyi DiskType = "tianyi"
    DiskAliyun DiskType = "aliyun"
)

// DiskAdapter 所有网盘必须实现此接口
type DiskAdapter interface {
    // Type 返回网盘类型
    Type() DiskType

    // --- 认证 ---
    // GetQRCode 生成扫码登录二维码（返回二维码内容 + 会话ID）
    GetQRCode(ctx context.Context) (*QRCode, error)
    // PollQRCode 轮询扫码状态，成功后返回 cookie
    PollQRCode(ctx context.Context, sessionID string) (*LoginResult, error)
    // ValidateCookie 校验 cookie 是否有效
    ValidateCookie(ctx context.Context, cookie string) error

    // --- 文件操作 ---
    ListDir(ctx context.Context, cookie, dirID string) ([]FileItem, error)
    MakeDir(ctx context.Context, cookie, parentID, name string) (string, error)
    DeleteFile(ctx context.Context, cookie, fileID string) error

    // --- 转存（核心）---
    // ParseShare 解析分享链接，拿到分享内的文件列表
    ParseShare(ctx context.Context, cookie, shareURL, passcode string) (*ShareInfo, error)
    // SaveToDir 从分享链接转存到自己的指定目录
    SaveToDir(ctx context.Context, cookie string, share *ShareInfo, targetDirID string) ([]string, error)

    // --- 播放 / 下载 ---
    // GetDirectLink 获取文件直链（用于播放/下载）
    GetDirectLink(ctx context.Context, cookie, fileID string) (*DirectLink, error)
    // GetDownloadChunks 获取分块下载所需的 range 信息（非会员加速用）
    GetDownloadChunks(ctx context.Context, cookie, fileID string, chunkSize int64) ([]Chunk, error)
}
```

**为什么这样设计：**
1. **统一接口** → 上层 Service 无需关心是哪个网盘，新增网盘只需实现接口 + 注册。
2. **认证与操作分离** → cookie 由「扫码」或「手动填写」获得，之后所有操作都带着 cookie，便于多账号管理。
3. **`SaveToDir` 是转存需求的核心** → 先 `ParseShare` 解析分享，再指定目标目录转存。
4. **`GetDownloadChunks` 是非会员加速的关键** → 通过分块 + 并发 range 请求突破单线程限速。

### 3.3 非会员加速原理

网盘对非会员的限制主要体现在**单连接限速**，而非总量限制。加速思路：

```
普通下载：  [======单连接======]  → 200KB/s 封顶

加速下载：  [==chunk1==]  并发
            [==chunk2==]  ─────→ 聚合速度 = 200KB/s × N
            [==chunk3==]
            ...
            [==chunkN==]

实现要点：
1. 先请求文件元信息，拿到 fileSize 和支持的 Accept-Ranges
2. 按固定大小（如 2MB）切分 chunk 列表
3. 用 N 个 goroutine（N=16~32，可配）并发发起 Range 请求
4. 落盘时按偏移量写入，或直接串流给播放器
```

参考实现：`netdisk-fast-download`（3.3k star，Java/Vert.x）实测夸克可达 5MB/s。

> **重要限制**：加速只能缓解单连接限速，**无法突破网盘的总量限速策略**，也无法绕过付费墙。若网盘侧做了 token 级限速，并发收益会衰减。这一点用户需知悉。

**另一种更稳的路线（推荐用于播放场景）**：**自建中转**。即后端把网盘文件下载到本地（用加速），再以标准 HTTP/HLS 分发给前端。好处：
- 前端播放体验统一（就是一个普通 HTTP 流）
- 支持转码（转成 HLS 标准格式，兼容所有设备）
- 支持息屏/后台播放（HTTP 流不依赖网盘会话）
- 可做防盗链、限速、缓存

代价是需要服务器带宽和存储。适合家庭/小规模自托管场景。

### 3.4 资源转码设计

不同来源资源格式杂乱（mkv / rmvb / avi / 各种编码），移动端和浏览器兼容性差。方案：

```
用户请求播放
     │
     ▼
检查是否存在转码缓存 (.m3u8 + .ts 分片)
     │
  ┌──┴──┐
 有     无
  │      │
  │      ▼
  │   判断是否为「浏览器友好格式」(mp4/h264/aac)
  │      │
  │   ┌──┴──┐
  │  是     否
  │   │      │
  │   │      ▼
  │   │   加入转码任务队列 (ffmpeg)
  │   │   ffmpeg -i src.mkv \
  │   │     -c:v libx264 -c:a aac \
  │   │     -hls_time 10 -hls_list_size 0 \
  │   │     -f hls output.m3u8
  │   │      │
  │   │      ▼
  │   │   边转边播（转出第一个分片即可开始播放）
  │   │
  └───┴──► 返回播放地址
```

关键点：
- **边转边播**：不等整个文件转完，ffmpeg 输出 HLS 分片后即可播放，用户体验好。
- **转码参数按需降级**：低配设备可降到 720p / 更低码率。
- **惰性转码**：只在首次播放时转，结果缓存复用。

### 3.5 目录树模型

需求要求「树状结构，可自己增加层级目录」，且前端「一级图标 → 二级 → 文件夹图标」。

采用**自引用邻接表**（简单可靠，适合层级不深的学习资源）：

```sql
CREATE TABLE categories (
    id          BIGSERIAL PRIMARY KEY,
    parent_id   BIGINT DEFAULT NULL,      -- NULL 表示根节点
    name        VARCHAR(100) NOT NULL,    -- 目录名，如「乐学英语」
    icon        VARCHAR(200),             -- 图标标识/URL，子供儿童化图标
    description TEXT,
    sort_order  INT DEFAULT 0,            -- 同级排序
    level       INT DEFAULT 1,            -- 层级，便于查询
    path        VARCHAR(500),             -- 物化路径 /1/12/35/，便于子树查询
    is_public   BOOLEAN DEFAULT FALSE,    -- 是否公开（无需授权即可访问）
    created_at  TIMESTAMPTZ,
    updated_at  TIMESTAMPTZ,
    deleted_at  TIMESTAMPTZ               -- 软删除
);
CREATE INDEX idx_categories_parent ON categories(parent_id);
CREATE INDEX idx_categories_path ON categories(path);
```

**为什么加 `path` 字段**：查询「乐学英语」下的所有子目录/资源时，一条 `path LIKE '/1/%'` 即可，避免递归查询，性能好。

示例树：
```
/  根
├── 乐学英语        (path=/1/)          icon=english
│   ├── 新概念英语   (path=/1/11/)       icon=book
│   ├── 剑桥少儿英语 (path=/1/12/)       icon=star
│   └── 英语儿歌     (path=/1/13/)       icon=music
├── 国学经典        (path=/2/)          icon=chinese
│   ├── 三字经      (path=/2/21/)
│   └── 唐诗三百首   (path=/2/22/)
├── 开心故事        (path=/3/)          icon=story
└── 数学思维        (path=/4/)          icon=math
```

### 3.6 权限模型

需求：「新建用户，指定权限有效时间，能访问哪个目录」。

采用**用户 ↔ 目录 授权表** + **有效期**：

```sql
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    username      VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(200) NOT NULL,
    nickname      VARCHAR(50),
    role          VARCHAR(20) DEFAULT 'kid',   -- admin / kid
    avatar        VARCHAR(200),
    grade         VARCHAR(20),                 -- 年级，供 AI 分析用
    status        SMALLINT DEFAULT 1,          -- 1 启用 0 禁用
    expires_at    TIMESTAMPTZ,                 -- 账号整体有效期
    created_at    TIMESTAMPTZ,
    updated_at    TIMESTAMPTZ,
    deleted_at    TIMESTAMPTZ
);

-- 目录级授权：某用户可访问某目录，到某时间为止
CREATE TABLE user_category_grants (
    id          BIGSERIAL PRIMARY KEY,
    user_id     BIGINT NOT NULL,
    category_id BIGINT NOT NULL,
    can_download BOOLEAN DEFAULT TRUE,
    expires_at  TIMESTAMPTZ,          -- 该目录授权的有效期
    created_at  TIMESTAMPTZ,
    UNIQUE(user_id, category_id)
);
```

**权限判定逻辑**：
1. 检查 `users.status = 1` 且未过期（`expires_at IS NULL OR expires_at > now()`）
2. 检查请求的 `category_id` 是否在用户的授权列表中且授权未过期
3. 若目录 `is_public = true`，跳过第 2 步
4. 若用户 `role = admin`，放行全部

## 4. 关键业务流程

### 4.1 资源搜索 → 转存 流程

```
管理员在后台搜索「新概念英语」
        │
        ▼
core-server 调 pansou  POST /api/search
        │
        ▼
返回多网盘聚合结果 (quark/baidu/uc/tianyi 分类)
        │
        ▼
调 pansou POST /api/check/links 或 PanCheck 批量检测存活
        │
        ▼
前端展示：有效资源 ✅ / 失效资源 ❌
        │
        ▼
管理员选一条夸克资源 → 选择「转存到：乐学英语/新概念英语」
        │
        ▼
创建 transfer_task (status=pending) → 入 Redis 队列
        │
        ▼
worker 取出任务：
  1. 取该网盘账号 cookie
  2. adapter.ParseShare(分享链接, 提取码)
  3. adapter.SaveToDir(cookie, share, 目标目录ID)
  4. 更新任务状态 success/failed
        │
        ▼
转存成功后，在 resources 表建立记录，关联到 categories
```

### 4.2 扫码绑定网盘流程

```
后台「网盘账号」页 → 点击「添加夸克账号」
        │
        ▼
core-server 调 adapter.GetQRCode() → 得到二维码内容
        │
        ▼
前端渲染二维码，同时开始轮询
   GET /api/disk/accounts/qr/{sessionId}
        │
        ▼
用户手机 App 扫码并确认
        │
        ▼
adapter.PollQRCode 拿到 cookie → 加密存储到 disk_accounts
        │
        ▼
后端调 adapter.ValidateCookie 验证 → 返回账号昵称/容量
```

### 4.3 前端播放（含加速与息屏）流程

```
孩子在 PWA/APK 点击一个视频
        │
        ▼
GET /api/play/{resourceId}
        │
        ▼
后端判断：
  1. 权限校验（该用户是否有权访问此资源所属目录）
  2. 是否已有播放地址缓存
        │
   ┌────┴────┐
  有         无
   │          │
   │          ▼
   │    策略选择：
   │    A. 直链模式：adapter.GetDirectLink → 返回网盘直链(带加速代理)
   │    B. 中转模式：下载到本地 → 转码 HLS → 返回本地 m3u8
   │          │
   │          ▼
   │    缓存播放地址 (TTL)
   │          │
   └────┬─────┘
        ▼
返回给前端播放器
        │
        ▼
前端 xgplayer 播放；视频元素设置
  - playsinline
  - MediaSession API (锁屏控制)
  - 原生壳拦截 onPause → 保持后台播放
        │
        ▼
定时上报播放进度 → play_records
```

## 6. 安全设计

| 风险点 | 措施 |
|---|---|
| 网盘 cookie 泄露 | 数据库中以 AES-256-GCM 加密存储；解密密钥通过环境变量注入 |
| JWT 泄露 | 短有效期（access 2h + refresh 7d）；支持主动吊销 |
| 越权访问资源 | 每次资源访问都做「用户-目录」授权链校验 |
| 播放地址被分享 | 播放地址签名 + 短 TTL + 绑定用户 |
| 转存滥用 | 转存任务限流（单账号 QPS 限制） |
| 后台被爆破 | 登录失败锁定 + 验证码 |
| SSRF | 网盘直链调用做域名白名单 |

## 8. 风险与限制说明

1. **网盘协议的不稳定性**：网盘官方 API 可能随时变更，适配层需要持续维护。这是所有此类项目共同面临的问题。
2. **非会员加速的天花板**：加速只能突破单连接限速，无法突破账号级别的总量限速与付费墙。
3. **账号风控**：高频转存/下载可能触发网盘风控导致账号被限制，需做限流。
4. **版权合规**：系统仅提供技术能力，资源内容需使用者自行确保合法来源。
5. **转码开销**：视频转码是 CPU 密集型任务，需评估服务器性能，建议限制并发转码数。
