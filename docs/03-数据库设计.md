## 核心表结构

### users — 用户

```sql
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    created_at    TIMESTAMPTZ,
    updated_at    TIMESTAMPTZ,
    deleted_at    TIMESTAMPTZ,
    username      VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(200) NOT NULL,       -- bcrypt
    nickname      VARCHAR(50),
    role          VARCHAR(20) DEFAULT 'kid',   -- admin / kid
    avatar        VARCHAR(300),
    grade         VARCHAR(20),                 -- 年级，供 AI 分析
    age           INT,
    status        SMALLINT DEFAULT 1,          -- 1 启用 / 0 禁用
    expires_at    TIMESTAMPTZ,                 -- 账号有效期，NULL=永久
    last_login_at TIMESTAMPTZ
);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_status ON users(status);
```

**设计说明**：
- `expires_at` 支持需求中的「指定权限有效时间」
- `role` 区分管理员和孩子，一套表便于统一认证
- 软删除（`deleted_at`）避免误删导致数据难以恢复

### categories — 目录树

```sql
CREATE TABLE categories (
    id          BIGSERIAL PRIMARY KEY,
    created_at  TIMESTAMPTZ,
    updated_at  TIMESTAMPTZ,
    deleted_at  TIMESTAMPTZ,
    parent_id   BIGINT,                        -- NULL = 根
    name        VARCHAR(100) NOT NULL,
    icon        VARCHAR(200),                  -- 图标 key，如 english
    icon_url    VARCHAR(500),                  -- 自定义图标
    color       VARCHAR(30),                   -- 主题色
    description VARCHAR(500),
    sort_order  INT DEFAULT 0,
    level       INT DEFAULT 1,
    path        VARCHAR(500),                  -- 物化路径 /1/12/35/
    is_public   BOOLEAN DEFAULT FALSE
);
CREATE INDEX idx_categories_parent ON categories(parent_id);
CREATE INDEX idx_categories_path ON categories(path);
```

**设计说明**：
- 采用「邻接表 + 物化路径」混合方案
- `parent_id` 支持树形结构，前端可直接渲染
- `path` 冗余存储，使「查某目录下所有子孙」只需一次 `LIKE` 查询：

```sql
-- 查「乐学英语」(id=1) 下所有子孙目录
SELECT * FROM categories WHERE path LIKE '/1/%';

-- 查某目录下的所有资源（含子目录）
SELECT r.* FROM resources r
JOIN categories c ON r.category_id = c.id
WHERE c.path LIKE '/1/%' OR c.id = 1;
```

- 移动目录时需同步更新整棵子树的 `path` 和 `level`（见 `category.go` 的 `Move`）
- `icon` 存图标 key，前端映射为 emoji 或图标组件，便于儿童化展示

### user_category_grants — 目录授权

```sql
CREATE TABLE user_category_grants (
    id           BIGSERIAL PRIMARY KEY,
    created_at   TIMESTAMPTZ,
    updated_at   TIMESTAMPTZ,
    deleted_at   TIMESTAMPTZ,
    user_id      BIGINT NOT NULL,
    category_id  BIGINT NOT NULL,
    can_download BOOLEAN DEFAULT TRUE,
    expires_at   TIMESTAMPTZ,                  -- 该授权的有效期
    UNIQUE(user_id, category_id)
);
CREATE INDEX idx_grants_user ON user_category_grants(user_id);
CREATE INDEX idx_grants_category ON user_category_grants(category_id);
```

**权限判定逻辑**：

```
用户请求目录 C 的资源
  │
  ├─ 是管理员？ → 放行
  ├─ 账号已禁用/过期？ → 拒绝
  ├─ 目录 C 或其任一祖先 is_public？ → 放行
  ├─ 存在 grant(user, C 或 C 的任一祖先) 且未过期？ → 放行
  └─ 否则 → 拒绝
```

> 授权父目录 = 隐式获得所有子目录权限，这符合使用直觉（管理员给「乐学英语」授权即可看其下所有内容）。

### resources — 资源

```sql
CREATE TABLE resources (
    id                BIGSERIAL PRIMARY KEY,
    created_at        TIMESTAMPTZ,
    updated_at        TIMESTAMPTZ,
    deleted_at        TIMESTAMPTZ,
    category_id       BIGINT NOT NULL,
    title             VARCHAR(300) NOT NULL,
    description       TEXT,

    -- 网盘来源
    disk_type         VARCHAR(20),             -- quark/baidu/uc/tianyi
    share_url         VARCHAR(800),
    passcode          VARCHAR(50),
    share_id          VARCHAR(200),

    -- 转存后信息
    disk_account_id   BIGINT,
    owner_dir_id      VARCHAR(200),
    file_id           VARCHAR(200),

    -- 元信息
    media_type        VARCHAR(20),             -- video/audio/pdf/image
    cover             VARCHAR(800),
    file_count        INT,
    total_size        BIGINT,
    duration          INT,

    -- 状态
    status            VARCHAR(20) DEFAULT 'unknown',  -- alive/dead/unknown
    last_checked_at   TIMESTAMPTZ,

    tags              TEXT,                    -- JSON 数组
    sort_order        INT DEFAULT 0,
    view_count        BIGINT DEFAULT 0
);
CREATE INDEX idx_resources_category ON resources(category_id);
CREATE INDEX idx_resources_title ON resources(title);
CREATE INDEX idx_resources_disk_type ON resources(disk_type);
CREATE INDEX idx_resources_status ON resources(status);
```

### disk_accounts — 网盘账号

```sql
CREATE TABLE disk_accounts (
    id                BIGSERIAL PRIMARY KEY,
    created_at        TIMESTAMPTZ,
    updated_at        TIMESTAMPTZ,
    deleted_at        TIMESTAMPTZ,
    disk_type         VARCHAR(20) NOT NULL,
    nickname          VARCHAR(100),
    avatar            VARCHAR(500),

    cookie_encrypted  TEXT,                    -- AES-256-GCM 密文
    cookie_preview    VARCHAR(100),            -- 脱敏展示
    extra             TEXT,                    -- JSON，存 BDUSS/STOKEN 等

    status            VARCHAR(20) DEFAULT 'valid',
    last_check_at     TIMESTAMPTZ,
    capacity_used     BIGINT,
    capacity_total    BIGINT,
    is_default        BOOLEAN DEFAULT FALSE,
    rate_limit        INT DEFAULT 2,
    remark            VARCHAR(500)
);
```

**安全说明**：
- `cookie_encrypted` 使用 AES-256-GCM 加密，密钥来自 `SECURITY_COOKIE_ENCRYPT_KEY`
- `cookie_preview` 仅存脱敏后的片段（如 `__puus=abcd****wxyz`）供前端展示
- **cookie 绝不通过任何 API 返回给前端**

### study_records — 学习记录

```sql
CREATE TABLE study_records (
    id             BIGSERIAL PRIMARY KEY,
    created_at     TIMESTAMPTZ,
    updated_at     TIMESTAMPTZ,
    deleted_at     TIMESTAMPTZ,
    user_id        BIGINT NOT NULL,
    resource_id    BIGINT,
    category_id    BIGINT,
    category_name  VARCHAR(100),               -- 冗余，避免聚合时 JOIN
    resource_title VARCHAR(300),
    action         VARCHAR(30),                -- play_start/play_progress/play_finish/ai_chat
    duration       INT,                        -- 本次持续秒数
    position       INT,
    media_type     VARCHAR(20),
    happened_at    TIMESTAMPTZ NOT NULL,
    study_date     VARCHAR(10),                -- YYYY-MM-DD，冗余
    study_hour     INT                         -- 0-23，冗余
);
CREATE INDEX idx_study_user_time ON study_records(user_id, happened_at);
CREATE INDEX idx_study_date ON study_records(study_date);
CREATE INDEX idx_study_hour ON study_records(study_hour);
```

**设计说明**：
- `category_name` / `study_date` / `study_hour` 是冗余字段，牺牲一点写入性能换取聚合查询性能
- AI 学情分析需要按天/按科目/按时段聚合，冗余后可以纯索引扫描

## 索引策略

| 场景 | 索引 |
|---|---|
| 按目录查资源 | `idx_resources_category` |
| 按标题搜索资源 | `idx_resources_title`（可升级为 pg_trgm 全文索引） |
| 查某用户的学习记录 | `idx_study_user_time` |
| 按日期聚合学习时长 | `idx_study_date` |
| 目录树查询 | `idx_categories_parent` + `idx_categories_path` |
| 权限校验 | `idx_grants_user` + `idx_grants_category` |

### 可选：启用中文全文检索

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX idx_resources_title_trgm ON resources USING gin (title gin_trgm_ops);

-- 之后可用模糊匹配
SELECT * FROM resources WHERE title % '新概念英语';
```

## 数据保留策略

`study_records` 增长最快，建议定期归档：

```sql
-- 删除 1 年前的学习记录（保留 AI 报告）
DELETE FROM study_records WHERE happened_at < NOW() - INTERVAL '1 year';

-- 或按月分区（数据量大时）
```

## 迁移说明

项目使用 GORM AutoMigrate，启动时自动同步表结构：

```go
// internal/model/db.go
func AutoMigrate(db *gorm.DB) error {
    return db.AutoMigrate(AllModels()...)
}
```

**注意**：AutoMigrate 只做增量添加（新增表、新增列、新增索引），**不会删除列**。若需修改列类型或删除列，需手动写迁移 SQL。
